## 1. 分润计算 / 结算（优先）

### 1.1 状态机说明

```
订单支付成功
  → calculateForOrder
  → 分润记录 status = PENDING

订单到期（OrderSettlement cron / 手动到期）
  → 订单 status = SETTLED（本金+收益退回用户余额）
  → 分润仍为 PENDING（此时尚不入账）

CommissionSettlement（每 5 分钟 / 手动触发）
  → markSettledBatch：订单已 SETTLED 的分润 PENDING → SETTLED
  → payoutSettledBatch：SETTLED → PAID（余额入账 + wallet_log）
```

| 状态 | 含义 |
|------|------|
| `PENDING` | 已计算，待订单结算后进入结算池 |
| `SETTLED` | 已结算，待发放入账 |
| `PAID` | 已发放到余额 |
| `FROZEN` | 冻结 |
| `VOID` | 作废 |

### 1.2 正常路径：支付 → 待结算分润

| # | 步骤 | 操作 | 预期 | 勾选 |
|---|------|------|------|------|
| 1.2.1 | 准备推广关系 | 用 `promoter` 邀请码注册/绑定下线用户（如 `testuser`） | `user_relations` 存在父子关系 | ☐ |
| 1.2.2 | 充值 | H5：下线用户充值并完成 notify（或管理端调账） | 余额足够下单 | ☐ |
| 1.2.3 | 下单并支付 | H5：选产品下单 → `POST /orders/:id/pay` | 订单变为 `ACTIVE`/`PAID` | ☐ |
| 1.2.4 | 检查分润生成 | 管理端「佣金管理」或查库 `commissions` | 出现 `PENDING` 分润，金额按规则计算 | ☐ |
| 1.2.5 | 确认未提前入账 | 查推广员余额 / wallet_log | 支付瞬间**不应**因分润增加余额 | ☐ |

### 1.3 订单到期结算（本金+收益）

| # | 步骤 | 操作 | 预期 | 勾选 |
|---|------|------|------|------|
| 1.3.1 | 制造到期订单 | 将某 `ACTIVE` 订单 `end_date` 改为过去时间 | 订单满足到期条件 | ☐ |
| 1.3.2 | 等待/触发订单结算 | 等 1 分钟 cron，或依赖服务内结算任务 | 订单 `status=SETTLED`；用户余额增加本金+收益 | ☐ |
| 1.3.3 | 确认分润仍待结算 | 查对应 `commissions` | 仍为 `PENDING`（尚未 `PAID`） | ☐ |

### 1.4 分润结算发放（PENDING → SETTLED → PAID）

| # | 步骤 | 操作 | 预期 | 勾选 |
|---|------|------|------|------|
| 1.4.1 | 手动触发结算 | 管理端 token 调用：`POST /api/v1/admin/commissions/run-settlement` | `{"status":"success","data":{"settled":N,"paid":M}}` | ☐ |
| 1.4.2 | 校验状态流转 | 查对应分润记录 | `PENDING` → `SETTLED` → `PAID`；有 `settled_at`、`paid_at` | ☐ |
| 1.4.3 | 校验钱包入账 | 查推广员余额与 `wallet_logs` | 余额增加 = 分润金额；流水 `reference_type=COMMISSION` | ☐ |
| 1.4.4 | 幂等/空跑 | 再次调用 `run-settlement` | `settled=0, paid=0`，不重复入账 | ☐ |
| 1.4.5 | Cron 验证 | 观察后端日志（约每 5 分钟） | 出现 `job:commission-settlement finished` | ☐ |

### 1.5 边界与异常

| # | 场景 | 操作 | 预期 | 勾选 |
|---|------|------|------|------|
| 1.5.1 | 订单未 SETTLED | 仅有 `ACTIVE` 订单的 `PENDING` 分润时触发结算 | 不标记 SETTLED、不发放 | ☐ |
| 1.5.2 | 延迟天数 | 规则配置 `settle_delay_days>0`，订单刚 SETTLED | 未到延迟日不结算 | ☐ |
| 1.5.3 | 退款作废 | 对已产生分润的订单执行退款 | `PENDING/SETTLED` → `VOID`；已 `PAID` 走冲正 | ☐ |
| 1.5.4 | 冻结/解冻 | 管理端 freeze → unfreeze | 冻结期间不发放；解冻回 `SETTLED` 或 `PENDING` | ☐ |
| 1.5.5 | 人工补发 | `POST /admin/commissions/manual-credit` | 先 SETTLED 再入账为 PAID | ☐ |

### 1.6 H5 收益明细对齐

## 4. 常用 API 速查

### 管理端登录

```http
POST /api/v1/admin/auth/login
Content-Type: application/json

{"username":"admin","password":"123456"}
```

响应取顶层 `token`（不是 `data.access_token`）。

### 手动触发分润结算

```http
POST /api/v1/admin/commissions/run-settlement
Authorization: Bearer <admin_token>
```

### 佣金列表

```http
GET /api/v1/admin/commissions?page=1&page_size=20
Authorization: Bearer <admin_token>
```

### PowerShell 示例

```powershell
$login = Invoke-RestMethod -Uri "http://localhost:3000/api/v1/admin/auth/login" `
  -Method POST -ContentType "application/json" `
  -Body '{"username":"admin","password":"123456"}'
$token = $login.token
$headers = @{ Authorization = "Bearer $token" }

Invoke-RestMethod -Uri "http://localhost:3000/api/v1/admin/commissions/run-settlement" `
  -Method POST -Headers $headers
```

## 5. 数据库快速核对

```sql
-- 分润按状态统计
SELECT status, COUNT(*) AS cnt FROM commissions GROUP BY status;

-- 最近分润
SELECT id, biz_id, to_user_id, amount, status, settled_at, paid_at
FROM commissions ORDER BY id DESC LIMIT 20;

-- 订单状态
SELECT id, user_id, status, amount, end_date FROM orders ORDER BY id DESC LIMIT 20;

-- 分润入账流水
SELECT * FROM wallet_logs
WHERE reference_type = 'COMMISSION'
ORDER BY id DESC LIMIT 20;
```

也可在 `service` 目录执行：

```bash
node scripts/check-commission.mjs
node scripts/check-order-commissions.mjs
```

## 6. 通过标准（本批）

- [ ] 支付后分润为 `PENDING`，且不立即入账
- [ ] 订单 `SETTLED` 后，结算任务可将分润推到 `SETTLED` 再 `PAID`
- [ ] `PAID` 后余额与 `wallet_log` 金额一致，重复触发不重复入账
- [ ] H5 推广中心二维码可展示、可保存
- [ ] 扫码注册可绑定推广关系（若本批覆盖注册链路）

## 7. 已知注意点

1. 管理端登录 token 字段为响应顶层 `token`。
2. 订单结算与分润结算是**两个独立任务**：订单 cron 每分钟；分润 cron 每 5 分钟。
3. 若端口 3000 被占用，确认实际监听进程已加载最新 `run-settlement` 路由后再测。
4. H5 二维码依赖浏览器 `canvas`/`document`，请在 **H5 浏览器环境**验证（非小程序端）。
