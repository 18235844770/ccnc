# 模块四：订单管理 (Order Management)

## 1. 业务需求概述

订单管理模块汇集了全平台所有用户的投资记录。管理员通过此模块监控交易状态，排查用户反馈的“未到账”、“未结算”等问题，并掌握整体的资金流入情况。

### 核心功能点
1.  **全局订单列表**：查询全平台所有订单，不再局限于单个用户视角。
2.  **多维筛选**：支持按订单号、用户ID、产品名称、订单状态（待支付/已支付/计息中/已结算）、下单时间进行组合查询。
3.  **订单详情**：展示订单的生命周期节点（创建时间、支付时间、预计结算时间）及关联的收益信息。
4.  **状态监控**：识别异常订单（如支付后长时间未确认、到期未结算）。

## 2. 接口 API 文档

### 2.1 订单查询

#### 2.1.1 全局订单列表
*   **接口地址**: `GET /api/v1/admin/orders`
*   **权限标识**: `order:list`
*   **功能描述**: 分页查询所有用户的理财订单。

**请求参数 (Query)**:
| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `page` | int | 否 | 页码，默认 1 |
| `page_size` | int | 否 | 每页数量，默认 20 |
| `user_id` | int | 否 | 按用户筛选 |
| `order_id` | string | 否 | 按订单号模糊搜索 |
| `status` | int | 否 | 状态筛选: `0`=待支付, `1`=已支付, `2`=计息中, `3`=已过期/结束, `4`=已结算 |
| `start_time` | time | 否 | 下单时间起 (RFC3339) |
| `end_time` | time | 否 | 下单时间止 |

**响应参数**:
```json
{
  "status": "success",
  "data": {
    "total": 500,
    "list": [
      {
        "id": 202301010001,
        "user_id": 1001,
        "username": "user01",
        "product_id": 1,
        "amount": 1000.00,      // 投资本金
        "profit": 12.50,        // 预计/实际收益
        "status": 2,            // 2=计息中
        "created_at": "2023-01-01T10:00:00Z"
      }
    ]
  }
}
```

#### 2.1.2 订单详情
*   **接口地址**: `GET /api/v1/admin/orders/:id`
*   **权限标识**: `order:detail` *(注：该权限目前可能复用 `order:list` 或单独定义，当前代码主要通过列表返回精简信息，详情接口可视需求复用用户端接口逻辑但增加鉴权)*
*   **功能描述**: 获取订单的完整信息，包括支付流水号、收益计算明细等。

**响应参数**:
```json
{
  "status": "success",
  "data": {
    "id": 202301010001,
    "user_id": 1001,
    "product_name": "新手专享计划",
    "amount": 1000.00,
    "start_time": "2023-01-02T00:00:00Z", // 起息日
    "end_time": "2023-01-09T00:00:00Z",   // 到期日
    "status": 2,
    "payment_info": {
        "tx_hash": "0x...",
        "paid_at": "2023-01-01T10:05:00Z"
    }
  }
}
```

## 3. 关联业务说明

*   **状态流转**：
    *   `0 (Pending)` -> 用户发起，未支付。
    *   `1 (Paid)` -> 支付成功，等待起息（通常 T+0 或 T+1）。
    *   `2 (Active)` -> 计息中，不可赎回（定期产品）。
    *   `3 (Expired)` -> 到期，等待结算脚本处理。
    *   `4 (Settled)` -> 本金+收益已返还至用户余额。

*   **自动任务**：
    *   订单状态流转主要由后台定时任务 (`internal/task`) 驱动，管理员主要负责监控任务执行结果（通过查看订单状态是否如期变更）。
